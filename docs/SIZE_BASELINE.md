# سجل حجم الثنائي (Size Baseline)

بوابة الحجم تفرض سقف 4 ميبيبايت على ثنائي الإصدار (`se-cli`).

| التاريخ | الحجم (بايت) | ملاحظة |
|---|---|---|
| 2026-11-11 (إعادة بناء M0) | 474,160 | ملف إعادة البناء بعد حادثة فقدان البيئة |
| 2026-11-12 (M1) | 513,392 | نمو M1 المتوقع: أمر `run` (تقرير عربي + أعلام CLI)، بصمات الحالة FNV، سجل التتبّع بصيغة المرجع، تنفيذ الأوامر غير الرسمية الـ105 والمقاطعات على الناقل |
| 2026-11-12 (M2) | 541,928 |
| 2026-11-13 (M3.1+M3.2) | 572,376 | نمو M3 المتوقع: المتحكّمان القياسيان ببروتوكول strobe + سيناريو `--input-script`، وإطار اللوحات (Registry + اللوحات العشر + نافذة CHR) |
| 2026-11-13 (M3.3 الواجهة — استشاري، خارج البوابة) | 5,165,248 | ثنائي `se-frontend` (يحمل winit وsoftbuffer وحدهما — D-27)؛ بوابة الحجم تقيس `se-cli` فقط كما هي، وهذا سطر توثيقي لقياس الواجهة لا يخضع للبوابة |
| 2026-11-14 (M4.3 الواجهة مع cpal — استشاري، خارج البوابة) | 5,349,776 | ثنائي `se-frontend` بعد دخول cpal 0.18.2 (D-40): نمو +184,528 بايت عن M3.3 مقابل مكتبة الصوت ومرشّح الاختزال؛ البوابة تقيس `se-cli` فقط كما هي، وقياسها الفعلي في هذه الدفعة 614,272 بايت (النمو عن آخر صف M2 موثَّق يعود لنواة APU الكاملة بدفعة M4.2، وبوابة الحجم خضراء: ضمن سقف 4 ميبيبايت) |
 نمو M2 المتوقع: PPU كاملة (السجلات، خط الأنابيب، السبرايت، OAM DMA، NMI والقمع)، MMC1 الأدنى، مُرمّز PNG يدوي بلا تبعيات، تقرير بروتوكول blargg |
